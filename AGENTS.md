# Project Notes

- This is a static HTML/CSS/JavaScript game; serve the repository root with `python -m http.server 8000`.
- Regenerate `data/sentences.js` from `HSK Database/HSK_Grammar_Database_HSK1_to_5.xlsx` with `python tools/extract_sentences.py` from the repository root.
- Validate JavaScript with `node --check game.js` and `node --check data/sentences.js`.
- Sentence data uses `[Chinese, Pinyin, Thai, Grammar Focus, Tokens]`, grouped by HSK level in the global `SENTENCES` object.
- Vocabulary data uses `[Chinese, Pinyin, Thai]` in the global `VOCAB` object; validate it with `node --check data/vocab.js`.
- Vocabulary covers HSK 1–9: HSK 1–5 have Thai translations; HSK 6 and 7-9 use English from CC-CEDICT (or Thai if translated via Bing). Regenerate with `python tools/translate_hsk69.py` (reads `BING_TRANSLATE_KEY` env var for batch en→th translation; without key, keeps English).
- `data/vocab_extra.js` (global `VOCAB_EXTRA`) enriches HSK 6–9 with POS, alternative translations, real zh/en/th example sentences, and filled pinyin — generated by `python tools/enrich_hsk69.py` (requires `BING_TRANSLATE_KEY`; uses Bing Dictionary Lookup/Examples/Transliterate/Translate with per-phase checkpoints in `HSK Database/extra_*.json`; `--skip-pinyin`/`--skip-thai` flags available).
- The writing mode loads Hanzi Writer 3.7.3 (with SRI) and hanzi-writer-data 2.0.1 from jsDelivr. Internet access is required for uncached characters; load failures must not consume lives or writing time.
- Reuse the Hanzi Writer instance across characters and sessions because it registers document-level input listeners. Use `updateDimensions` when its container resizes so stroke coordinates remain accurate on mobile.
- Hanzi Writer's `drawingWidth` is in its 1024-unit character coordinate system, not CSS pixels; it scales with the writing canvas.
- Dictionary mode (`dict`) searches VOCAB (HSK 1–9) by pinyin/Chinese/Thai, speech, or handwriting. Speech engine is user-selectable via `#dictMicEngBtn` (🔀 auto / 🌐 google / 🤖 whisper, persisted in `cr_dict_mic_engine`, shared with `speak` mode): auto tries Web Speech API `zh-CN` (Google's service — unreachable where Google is blocked) then falls back; google uses Web Speech only (network errors show a hint instead of falling back); whisper skips Google entirely (useful in China — no 7s stall wait). The fallback is on-device Whisper (`whisper-tiny` ONNX quantized ~41MB committed in `models/whisper-tiny/`, loaded via self-hosted `@huggingface/transformers@3.7.6` in `vendor3/transformers.web.min.js` — that bundle imports bare specifiers `onnxruntime-common`/`onnxruntime-web`, resolved by the `<script type="importmap">` in `index.html` to `vendor3/ort.webgpu.min.mjs` (onnxruntime-web 1.22.0, self-contained bundle matching `ort-wasm-simd-threaded.jsep.mjs`/`.wasm` in `vendor3/`, fetched via `wasmPaths`); `env.localModelPath="models/"`, `env.backends.onnx.wasm.wasmPaths="vendor3/"`, `allowRemoteModels=false`, `dtype:"q8"` (maps to `*_quantized.onnx`)). Uses `device:"wasm"` (WebGPU produces multilingual gibberish with this q8 model — verified; `ort.webgpu.min.mjs` is only the EP/module bundle); falls back to `device:"webgpu"` only if wasm fails to load. `wasm.numThreads` is 1 when `!crossOriginIsolated` (plain servers/GitHub Pages lack COOP+COEP → no SharedArrayBuffer → pthread workers fail). Mic records via AudioContext+ScriptProcessor (silent gain tap), resamples to 16kHz, auto-stops at 12s; used when SpeechRecognition is missing, errors with `network`, or stalls >7s. Model load shows % progress (progress_callback) and times out at 120s. Handwriting uses Google Input Tools API (`inputtools.google.com/request?itc=zh-t-i0-handwrit`, POST ink as `[xs, ys, ts]` strokes) with HanziLookupJS (jsDelivr `gugray/HanziLookupJS`, mmah data) as offline fallback — strokes are stored as `[x, y, t]` so they feed both engines. Shows HSK level + example sentences from SENTENCES (HSK 1–5 only). Words without Thai translation show English + Bing Translator link (`https://www.bing.com/translator?from=zh&to=th&text=...`). Each result entry also has a `✍️ ดูเส้นขีด` button (`dictToggleStrokes`) that expands an inline HanziWriter `animateCharacter` stroke-order viewer — reuses `loadBombLibrary()` + the shared `bombCharData` data cache (missing chars cache `null` so they aren't refetched; network errors stay uncached for retry), one writer per expanded entry (animation only, no quiz listeners), char chips below the canvas pick which character to animate for multi-char words, 🔁 replays via `dictStrokePlay`, and `updateDimensions` is re-applied on reopen via `dictStrokeFit`.
- HSK 3.0 data source: `HSK Database/hsk30.csv` from `ivankra/hsk30` (11,092 words). English definitions from `HSK Database/cedict.txt` (CC-CEDICT). Both are gitignored.
- Background music: per-mode chiptune playlists in `MUSIC_THEMES` (game.js) — each mode key (meteor/vocab/sentence/fillblank/zombie/matching/bomb/trace) holds an array of 5 unique song objects; `music.start("<mode>")` shuffles them and loops forever (each song = 32-step melody repeated `SONG_LOOPS` times, then `advanceSong` moves on; reshuffle avoids repeating the last song). Per-song fields: bpm, waveform, 32-step melody (null = rest), 8-step bass roots, drum flags, mul — shared per-mode defaults live in `_MET`/`_VOC`/`_SEN`/`_FIL`/`_ZOM`/`_MAT`/`_BOM`/`_TRA` spread into each song. `dict` and `speak` modes play no music.
- PWA: `manifest.json` + `sw.js` (registered at the end of `index.html`, icons in `icons/` generated by PIL). `sw.js` precaches the app shell and uses stale-while-revalidate for same-origin + `cdn.jsdelivr.net`/`fonts.googleapis.com`/`fonts.gstatic.com` GETs — audio clips and the whisper model cache on first use. Bump `CACHE` version (`cr-v1`) to force clients to drop old caches.
- Pre-generated speech: `audio/zh/<word>.mp3` and `audio/th/<word>.mp3` for HSK 1–9 — HSK 1–5 by `python gen_audio.py`, HSK 6/7-9 by `python gen_vocab_audio.py` (repo root; reads `data/vocab.js` levels 6+7-9, dedups by first ｜-variant, retry ×5, rerun `--skip-zh`/`--skip-th` until "0 failed"; ~6,753 words ≈ 13.5k files, takes hours — missing files fall back to TTS in the meantime). edge-tts voices `zh-CN-XiaoxiaoNeural` / `th-TH-PremwadeeNeural`, rate -15% (requires `pip install edge-tts`; re-runs skip existing files; `--limit N`/`--skip-zh`/`--skip-th` flags). `gen_audio.py` is gitignored (kept out of GitHub like `tools/`); `audio/` IS committed for GitHub Pages. The bomb game, meteor game, vocab quiz, and zombie game play these files on word completion/correct hit (via `speakWordHit` → `playWordAudio`) and fall back to `speakSeq` TTS when a file is missing. `wordAudio.play` fetches + decodes the mp3s with WebAudio, trims the ~0.2s leading / ~1s trailing silence that edge-tts bakes in (`audioBounds`), and schedules clips back-to-back (~30ms gap). `了` is special-cased: it has two readings (HSK 1 particle `le` / HSK 3 verb `liǎo`) but the shared `了.mp3` was generated without context and says `liǎo`, so the particle uses the separate key `了-le` (`audio/zh/了-le.mp3` + `audio/th/了-le.mp3`). That zh clip is not TTS output — edge-tts reads a bare `了` as `liǎo` for every zh voice tested, and SSML `<phoneme>` is rejected by the endpoint, so the clip was cut from the particle in the same voice's "他走了" (F2-stable vowel, verified vs a `le`/`liǎo` F2 profile). `wordAudioKey(zh, pinyin)` (game.js) picks the key, and both `speakWordHit` and listen mode use it.
- `data/sentences_extra.js` (global `SENTENCES_EXTRA`): 200 LLM-written practice sentences (40 per HSK 1–5), same `[zh, pinyin, th, grammar, tokens]` format, merged into `SENTENCES` at runtime by game.js — kept in a separate file so regenerating `sentences.js` from the xlsx never loses them. Their audio was generated by `python gen_sentence_audio_extra.py` (repo root; edge-tts, same voices/rate; reads BOTH sentence files and skips existing, retry ×4, concurrency 5 — the th-TH voice rate-limits hard, rerun `--skip-zh` until "0 failed").
- Visual layer (style.css): a `:root` design-token block sits at the top (palette `--bg-*`/`--surface-*`/`--line-*`/`--fg-*`/accent, layered shadows `--sh-*`/`--hi-top`, radii `--r-*`, motion `--dur-*`/`--ease-*`) — prefer tokens over new literal colors in shared UI (menu, setup, buttons); older mode-specific colors are still literal and can be migrated per-mode. `#menu`/`#setup` get a pure-CSS ambient backdrop (`::before` aurora drift + `::after` star layer, both `z-index: 0` + `pointer-events: none`, with `#menu > *, #setup > *` lifted to `z-index: 1` so they never cover buttons), the hero title splits the emoji from `.title-text` so the gradient `background-clip: text` doesn't erase the 🚀, and `.cards .card` gets a stagger entrance driven purely by `:nth-child` delays (no JS). Cards deliberately avoid `backdrop-filter` (11 blurred cards over an animated backdrop janks mid-range Android); only the single `.setup` panel uses it. A trailing `@media (prefers-reduced-motion: reduce)` block disables just these decorative animations — no game logic listens to `animationend`/`transitionend`, so this is safe.
- Sentence speech: `audio/zh/<chinese sentence>.mp3` and `audio/th/<chinese sentence>.mp3` for every SENTENCES entry (HSK 1–5, 777 sentences × 2 langs) — the Thai clip is keyed by the Chinese sentence because Thai text contains `?` which is illegal in filenames. Generated by `python tools/gen_sentence_audio.py` (same voices/rate/flags as gen_audio.py; concurrency 8; writes `.tmp` then renames so failures never leave empty mp3s). The fill-blank mode plays zh+th via `speakSentence(s, true)` and the sentence-ordering mode plays zh only via `speakSentence(s)`; both fall back to `speakSeq` TTS when a file is missing.
- Level select: `#levelSelect` shows HSK 1–5 always; `.vocab-level` buttons (HSK 6, HSK 7-9) appear only for VOCAB-based modes (meteor, zombie, vocab, matching, bomb, trace) — sentence modes (sent/fillblank/speak) only have HSK 1–5 data. If a hidden level was selected it is deselected on mode switch.
- Speaking practice mode (`speak`, เกมฝึกพูด): shows a SENTENCES entry (HSK 1–5), auto-plays its zh audio, then grades the user's speech. ASR reuses the dict-mode pipeline (Web Speech `zh-CN` + `loadDictWhisper`/`dictResample16k` Whisper fallback on `network` error or >7s stall). Grading is `spkAlign` — a Levenshtein alignment over Chinese chars only (`normZh` strips punctuation); homophones count as correct (same tone-stripped pinyin via the sentence's own pinyin or `dictPinyinIndex`), traditional chars are mapped through `TRAD2SIMP` for Whisper output. Green/red per-char verdict in `#spkCard`, "คุณพูดว่า" transcript in `#spkHeard`; wrong answers replay the correct audio and retry the same sentence. No background music (it would bleed into the mic); best score key `cr_best_hsk<level>_speak`.
- Sentence copying mode (`copy`, เกมเขียนเป็นประโยค): shows a random SENTENCES entry (HSK 1–5) for the user to copy into a notebook — shuffled deck with no repeats until exhausted (`cpAdvance`), auto-plays zh audio via `speakSentence`, no score/lives, plays the `sentence` music theme. Tapping a token chip (`cpOpenStrokes`) opens an inline HanziWriter `loopCharacterAnimation` stroke-order viewer reusing `loadBombLibrary()` + the shared `bombCharData` cache (one persistent `cpWriter` instance, `updateDimensions` on reopen/resize via `cpStrokeFit`, per-char chips via `cpStrokePlay`). "ข้าม" and "ประโยคถัดไป" both call `cpAdvance`. In `cpWriteMode === "on"` (เขียนในเกม) the advance button lives inside `#cpWrite` as `#cpWriteNextBtn` (`.cpw-next`, directly under the character chips) and stays `disabled`/grey until `cp.writeIndex` reaches `cp.writeChars.length` — `cpWriteNextEnabled()` is driven from `renderCpWriteChips()`; the duplicate `#cpNextBtn` in the bottom bar is hidden so the gating can't be bypassed (use "ข้าม" to skip, e.g. when stroke data fails to load). Tapping a word in the sentence (`cpRender` builds `#cpZh` via `cpRenderSentence` — one `.cp-zh-tok` button per `s[4]` token) opens the floating `#cpWordPopup` with pinyin + Thai meaning (+ POS from VOCAB_EXTRA, `cpWordPos`) anchored above the tapped word — no extra panel, works in both write modes. Lookup is `cpLookupWord` over a `cpWordIndex()` map built from VOCAB HSK 1–9 (handles `爸爸｜爸` variant pairs and TRAD2SIMP for traditional input); a whole-word miss falls back to greedy `cpSegment` so 航空公司 shows 航空 + 公司. Close button, outside `pointerdown`, Escape, scroll, or a new sentence call `cpHideWordPopup`; `resize` re-anchors it while the tapped word still exists.
- Listening practice mode (`listen`, เกมฝึกฟัง): endless zh→th audio review for commuting — setup picks type (คำศัพท์ = VOCAB HSK 1–9 / ประโยค = SENTENCES HSK 1–5; the `.vocab-level` buttons toggle when `lisType` changes) and gap (`lisGap` 0.8/1.2/2s — measured from audio END to next item, since clip lengths vary). `lisAdvance` draws from a shuffled deck with no repeats until exhausted, then reshuffles avoiding the last-played item. `wordAudio.play(items, onDone)` / `speakSeq(parts, onDone)` accept a completion callback — TTS fallback `onDone` is guarded by `speechSeqId` (bumped in `stopSpeech`) so cancelled utterances don't advance the queue. No music, no score; a Screen Wake Lock (`lisRequestWake`) keeps the display on; `visibilitychange` does NOT pause it — on return it re-requests the lock and replays the current item to recover a suspended AudioContext.
- Handwriting copy mode (`trace`, เกมคัดลายมือ / 10 ช่อง): picks a random VOCAB word from the selected HSK level (HSK 1–9 via `bombVocabulary(level)`, same deck logic as bomb/copy — reshuffles when exhausted and avoids repeating the last word) and asks the user to copy that same word into **10 slots** (`TC_SLOTS`). A multi-char word renders one sub-cell per character inside each slot (per request "ข") — 2 chars × 10 slots = 20 HanziWriter instances; `#tcGrid` uses 2 columns, switching to 1 column (`.wide`) when the word has ≥3 characters so the cells stay writable; a 1-char word gets `.single` so its box is exactly the same size as a 2-char word's box (half the slot's inner width, centered) instead of stretching to fill the slot. The whole writing-box layout scales from one multiplier, `--tc-scale` on `#trace` (currently `.7` = 30% smaller; width/gaps/paddings/frame/radius are all `calc(base * var(--tc-scale))`, so 1-, 2- and 3-char words shrink in the same proportion). Writing is **sequential**: only one slot is active at a time (others `.locked`), the slot's characters run one after another via `HanziWriter.quiz()` (same options as `cpWriteChar`: `leniency 1.4`, `markStrokeCorrectAfterMisses 4`, outline on/off from `tcOutline`) — `tcQuizChar` sets `showHintAfterMisses: 1` so the red hint (the stroke you should have drawn, `highlightColor #e5484d`) shows from the **first** wrong attempt; that number must stay below `markStrokeCorrectAfterMisses` (4), because on the attempt that auto-accepts a stroke HanziWriter takes the success branch and skips the hint render entirely — the old `tcOutline ? 4 : 1` meant the red hint could never appear while the guide was on (the default), so mistakes had no on-screen feedback until ✅ ตรวจ (`cpWriteChar` uses the same `showHintAfterMisses: 1` for the same reason — its hint line is green, `highlightColor #26a477`), and when a slot finishes `tcCompleteSlot` activates the next not-done slot. The score is **deferred**: per-stroke mistakes are accumulated in `slot.chars[k].wrongStrokes`/`attempts` but nothing is shown until all 10 slots are done and the user presses `#tcCheckBtn` (`tcCheck`), which scores `(strokes − wrongStrokes)/strokes` per char, averages the 10 slots → %, saves `cr_best_hsk<level>_trace`, marks each slot ⭐ (perfect) or `✗ n`, and reveals the correct character (`showOutline`) plus a **persistent red overlay** of the wrong strokes (`tcMarkWrong` draws polylines from `bombCharData.medians` mapped with `getScreenCTM()` into an absolutely-positioned `.tc-wrong-overlay` SVG — the transient `highlightStroke` fades, so we draw our own). `#tcRetryBtn` ("ลองใหม่ช่องที่ผิด") resets only the wrong slots and re-activates them; `#tcNextBtn`/`#tcSkipBtn` draw the next non-repeating word. Tapping any slot in the result phase plays `animateCharacter` for that slot. Writer `size` is set to the cell's real `clientWidth` (not capped) so the configured dimensions match the CSS-stretched SVG and `getScreenCTM`-based coordinates stay accurate; `tcFitWriters` re-fits + re-marks on `resize`. Async chains are invalidated by a **globally unique** `tcSeqCounter` (never resets per word — a per-word counter let stale chains from a previous word/session collide and crash on `slot.cells[k]`); writers also expose `_tcResolve` so `stopTrace`/`nextTraceWord` can unblock a pending `tcQuizChar`. Plays the `trace` music theme; pencil scratch sound via `pencilAllowed` on `#tcGrid` pointer events.
