# Project Notes

- This is a static HTML/CSS/JavaScript game; serve the repository root with `python serve.py` (gitignored dev server on port 8000: `--port`/`--host`/`--open`; it implements HTTP Range requests, which `python -m http.server` does not — without Range the browser reports `audio.seekable = [0, 0]` and the podcast's tap-a-sentence-to-jump can only restart from 0:00).
- Regenerate `data/sentences.js` from `HSK Database/HSK_Grammar_Database_HSK1_to_5.xlsx` with `python tools/extract_sentences.py` from the repository root.
- Validate JavaScript with `node --check` on every `js/*.js` file (the former single `game.js` is now split — see below) and `node --check data/sentences.js`.
- The game code lives in `js/` as 14 ordered classic scripts (previously one ~9k-line `game.js`): `01-state.js` (DOM refs, vocabulary categories, sentence merges), `02-audio.js` (WebAudio/sfx, TTS, pre-generated audio, background music), `03-helpers.js` (helpers, glow/bloom, difficulty, game flow), `04-quiz.js` (vocab quiz, sentence translation quiz, sentence ordering, fill-in-the-blank), `05-meteor.js` (meteor flight mode: meteors/options/effects/draw/loop), `06-zombie.js` (zombie shooter), `07-menu.js` (menu controls, matching + bomb modes, FX), `08-dict.js` (dictionary mode incl. Whisper ASR + handwriting), `09-speak.js` (speaking practice), `10-listen.js` (listening practice), `11-copy.js` (sentence copying + free writing), `12-trace.js` (handwriting copy + category selector init + Android back + app wiring), `13-podcast.js` (MaoMi podcast list, native audio player, transcript karaoke + vocabulary lookup), `14-reader.js` (private HSK 1-3 story list/player, pinyin toggle, karaoke word highlight, and Chinese-Thai turn playback; APK-only, with localhost preview). Load order in `index.html` matters and must stay numeric. All files are classic scripts sharing one global scope; each begins with `"use strict";` (the original was a single strict script). Only `toggleMute()` is declared early in `01-state.js` (rather than at the end) because later files pass it by reference while wiring click handlers at load time — function declarations hoist only within their own file. When moving code between files, keep the same load order and re-run the browser smoke test.
- Sentence data uses `[Chinese, Pinyin, Thai, Grammar Focus, Tokens]`, grouped by HSK level in the global `SENTENCES` object (levels 1–9 after the runtime merges described below).
- Vocabulary data uses `[Chinese, Pinyin, Thai]` in the global `VOCAB` object; validate it with `node --check data/vocab.js`.
- Vocabulary covers HSK 1–9: HSK 1–5 have Thai translations; HSK 6 and 7-9 use English from CC-CEDICT (or Thai if translated via Bing). Regenerate with `python tools/translate_hsk69.py` (reads `BING_TRANSLATE_KEY` env var for batch en→th translation; without key, keeps English).
- `data/vocab_extra.js` (global `VOCAB_EXTRA`) enriches HSK 6–9 with POS, alternative translations, real zh/en/th example sentences, and filled pinyin — generated by `python tools/enrich_hsk69.py` (requires `BING_TRANSLATE_KEY`; uses Bing Dictionary Lookup/Examples/Transliterate/Translate with per-phase checkpoints in `HSK Database/extra_*.json`; `--skip-pinyin`/`--skip-thai` flags available).
- The writing mode loads Hanzi Writer 3.7.3 (with SRI) and hanzi-writer-data 2.0.1 from jsDelivr. Internet access is required for uncached characters; load failures must not consume lives or writing time.
- Reuse the Hanzi Writer instance across characters and sessions because it registers document-level input listeners. Use `updateDimensions` when its container resizes so stroke coordinates remain accurate on mobile.
- Hanzi Writer's `drawingWidth` is in its 1024-unit character coordinate system, not CSS pixels; it scales with the writing canvas.
- Dictionary mode (`dict`) searches VOCAB (HSK 1–9) by pinyin/Chinese/Thai, speech, or handwriting. Speech engine is user-selectable via `#dictMicEngBtn` (🔀 auto / 🌐 google / 🤖 whisper, persisted in `cr_dict_mic_engine`, shared with `speak` mode): auto tries Web Speech API `zh-CN` (Google's service — unreachable where Google is blocked) then falls back; google uses Web Speech only (network errors show a hint instead of falling back); whisper skips Google entirely (useful in China — no 7s stall wait). The fallback is on-device Whisper (`whisper-tiny` ONNX quantized ~41MB committed in `models/whisper-tiny/`, loaded via self-hosted `@huggingface/transformers@3.7.6` in `vendor3/transformers.web.min.js` — that bundle imports bare specifiers `onnxruntime-common`/`onnxruntime-web`, resolved by the `<script type="importmap">` in `index.html` to `vendor3/ort.webgpu.min.mjs` (onnxruntime-web 1.22.0, self-contained bundle matching `ort-wasm-simd-threaded.jsep.mjs`/`.wasm` in `vendor3/`, fetched via `wasmPaths`); `env.localModelPath="models/"`, `env.backends.onnx.wasm.wasmPaths="vendor3/"`, `allowRemoteModels=false`, `dtype:"q8"` (maps to `*_quantized.onnx`)). Uses `device:"wasm"` (WebGPU produces multilingual gibberish with this q8 model — verified; `ort.webgpu.min.mjs` is only the EP/module bundle); falls back to `device:"webgpu"` only if wasm fails to load. `wasm.numThreads` is 1 when `!crossOriginIsolated` (plain servers/GitHub Pages lack COOP+COEP → no SharedArrayBuffer → pthread workers fail). Mic records via AudioContext+ScriptProcessor (silent gain tap), resamples to 16kHz, auto-stops at 12s; used when SpeechRecognition is missing, errors with `network`, or stalls >7s. Model load shows % progress (progress_callback) and times out at 120s. Handwriting uses Google Input Tools API (`inputtools.google.com/request?itc=zh-t-i0-handwrit`, POST ink as `[xs, ys, ts]` strokes) with HanziLookupJS (jsDelivr `gugray/HanziLookupJS`, mmah data) as offline fallback — strokes are stored as `[x, y, t]` so they feed both engines. Shows HSK level + example sentences from SENTENCES (HSK 1–5 only). Words without Thai translation show English + Bing Translator link (`https://www.bing.com/translator?from=zh&to=th&text=...`). Each result entry also has a `✍️ ดูเส้นขีด` button (`dictToggleStrokes`) that expands an inline HanziWriter `animateCharacter` stroke-order viewer — reuses `loadBombLibrary()` + the shared `bombCharData` data cache (missing chars cache `null` so they aren't refetched; network errors stay uncached for retry), one writer per expanded entry (animation only, no quiz listeners), char chips below the canvas pick which character to animate for multi-char words, 🔁 replays via `dictStrokePlay`, and `updateDimensions` is re-applied on reopen via `dictStrokeFit`.
- HSK 3.0 data source: `HSK Database/hsk30.csv` from `ivankra/hsk30` (11,092 words). English definitions from `HSK Database/cedict.txt` (CC-CEDICT). Both are gitignored.
- Background music: per-mode synth-orchestra playlists in `MUSIC_THEMES` (game.js) — each mode key (meteor/vocab/sentence/fillblank/zombie/matching/bomb/trace) holds an array of 5 unique song objects; `music.start("<mode>")` shuffles them and loops forever (each song = 32-step melody repeated `SONG_LOOPS` times, then `advanceSong` moves on; reshuffle avoids repeating the last song). Per-song fields: bpm, waveform, 32-step melody (null = rest), 8-step bass roots, drum flags, mul — shared per-mode defaults live in `_MET`/`_VOC`/`_SEN`/`_FIL`/`_ZOM`/`_MAT`/`_BOM`/`_TRA` spread into each song, plus the newer swing/pad/arp/detune/base (see below). `dict` and `speak` modes play no music. **Signal graph** (`music.buildGraph()`): per-layer gains (`drums/bass/pad/arp/lead/perc`, send amounts in `LAYER_FX`) → dry + reverb/delay sends → `master` (mute + `duckMusic`) → `DynamicsCompressor` limiter → destination. Reverb is a `ConvolverNode` with an **impulse response generated in JS** (`makeIR`, noise × power decay, no asset) and is skipped when `navigator.hardwareConcurrency <= 4`; the delay is a tempo-synced ping-pong (dotted-8th, synced in `syncDelay()` — which must be called again *after* `getAC()` builds the graph, since `loadSong()` runs before it). **Voices** (`music.tone`): 1 + 2 detuned oscillators (level divided by √n so loudness matches the old single-osc voice) + optional sub-oscillator for bass + per-voice lowpass with envelope + full ADSR + `StereoPanner` (`pan`); percussion lives in `kick/snare/hat/shaker/tom/bell/crash` plus a shared 1-second noise buffer (`nz`), with humanized timing (`human()`). **Song structure** is derived, not authored: `chordAt(s)` guesses each half-bar chord from `roots[0]`/`roots[4]` + the melody's third (3 semitones = minor, 4 = major), `pad()` holds that chord in 3 voices spread across the stereo field, `arp()` cycles its chord tones as 8th notes, drum fills (`tom`) land on the last 2 steps of every other loop and a `crash` opens the loop after. **Adaptive music**: `music.setIntensity(0..1)` (also `nudge()`) opens layers progressively in `applyIntensity()` (perc from .45, arp from .3, pad/lead/drums get slightly louder); intensity decays toward the mode's `base` at 0.7%/step, is reset to `base` on `music.start()`, and is driven by the game at: bomb mode (`renderBombTimer` → `1 - frac` remaining), meteor (`hitGround` → `1 - lives/3`), and every correct/wrong answer (`sfx.correct`/`sfx.wrong` → `nudge(+.05/-.12)`).

- Pre-generated speech: `audio/zh/<word>.mp3` and `audio/th/<word>.mp3` for HSK 1–9 — HSK 1–5 by `python gen_audio.py`, HSK 6/7-9 by `python gen_vocab_audio.py` (repo root; reads `data/vocab.js` levels 6+7-9, dedups by first ｜-variant, retry ×5, rerun `--skip-zh`/`--skip-th` until "0 failed"; ~6,753 words ≈ 13.5k files, takes hours — missing files fall back to TTS in the meantime). edge-tts voices `zh-CN-XiaoxiaoNeural` / `th-TH-PremwadeeNeural`, rate -15% (requires `pip install edge-tts`; re-runs skip existing files; `--limit N`/`--skip-zh`/`--skip-th` flags). `gen_audio.py` is gitignored (kept out of GitHub like `tools/`); `audio/` IS committed for GitHub Pages. The bomb game, meteor game, vocab quiz, and zombie game play these files on word completion/correct hit (via `speakWordHit` → `playWordAudio`) and fall back to `speakSeq` TTS when a file is missing. The bomb game also reads **each written character** as it is completed — `completeBombCharacter` calls `speakChar(s.chars[s.charIndex])` for every character except the last, which plays the full word via `speakWordHit(s.word)` (`speakChar` in `js/02-audio.js` plays `audio/zh/<char>.mp3` through `wordAudio`, TTS as fallback). This must not go back to `speak()`: Android WebView has **no** `speechSynthesis` at all (Chromium disables the Web Speech API in WebView), so a TTS-only character is silent in the APK while an mp3 is audible. Every single character used by the vocab packs therefore has its own clip — the ones that are not standalone vocab words are filled in by `python tools/gen_char_audio.py` (edge-tts, same voice/rate as `gen_audio.py`, skips existing files, `--limit N` for a smoke test, `--words` to also fill missing full-word clips; ~1,510 files). `wordAudio.play` fetches + decodes the mp3s with WebAudio, trims the ~0.2s leading / ~1s trailing silence that edge-tts bakes in (`audioBounds`), and schedules clips back-to-back (~30ms gap). `了` is special-cased: it has two readings (HSK 1 particle `le` / HSK 3 verb `liǎo`) but the shared `了.mp3` was generated without context and says `liǎo`, so the particle uses the separate key `了-le` (`audio/zh/了-le.mp3` + `audio/th/了-le.mp3`). That zh clip is not TTS output — edge-tts reads a bare `了` as `liǎo` for every zh voice tested, and SSML `<phoneme>` is rejected by the endpoint, so the clip was cut from the particle in the same voice's "他走了" (F2-stable vowel, verified vs a `le`/`liǎo` F2 profile). `wordAudioKey(zh, pinyin)` (game.js) picks the key, and both `speakWordHit` and listen mode use it.
- `data/sentences_extra.js` (global `SENTENCES_EXTRA`): 200 LLM-written practice sentences (40 per HSK 1–5), same `[zh, pinyin, th, grammar, tokens]` format, merged into `SENTENCES` at runtime by game.js — kept in a separate file so regenerating `sentences.js` from the xlsx never loses them. - `data/sentences_hsk69.js` (global `SENTENCES_HSK69`): grammar sentences for HSK 6 (98) and HSK 7-9 (192) — 290 sentences total, merged into `SENTENCES` at runtime right after `SENTENCES_EXTRA`. Each of the 145 official HSK 3.0 grammar points (49 + 96, 考试大纲 Nov 2025, data from Gushi <https://gushichinese.com/hsk-3.0/downloads> CC BY-SA 4.0, sources committed in `HSK Database/grammar69_hsk6.csv`/`grammar69_hsk79.csv`) gets the official example sentence plus one LLM-written extra, with hand-written pinyin (no-sandhi tone marks applied for 不/一), Thai translation and Thai grammar-focus label. Rebuild with `python tools/build_grammar69.py` (matches the Thai JSONs `HSK Database/grammar69_th_*.json` to the CSVs by index + normalized point name, cross-checks pinyin against pypinyin — report only, pypinyin does not apply 不/一 sandhi nor dictionary neutral tones, keeps greedy-token segmentation from VOCAB). Pinyin written by hand was reviewed against that report; pypinyin polyphone errors found: 都→dū, 倒是→dǎo, 照片→piān, 将→jiàng, 闷(闷热)→mèn, 点着→zháo, 睡不着→zhe (mine follows the dictionary).
- Visual layer (style.css): a `:root` design-token block sits at the top (palette `--bg-*`/`--surface-*`/`--line-*`/`--fg-*`/accent, layered shadows `--sh-*`/`--hi-top`, radii `--r-*`, motion `--dur-*`/`--ease-*`) — prefer tokens over new literal colors in shared UI (menu, setup, buttons); older mode-specific colors are still literal and can be migrated per-mode. **Font tokens** `--font-ui` (base, applied on `html, body`) and `--font-pinyin` (pinyin) put **Noto Sans** ahead of Noto Sans Thai / Noto Sans SC: all three families cover the Latin-Extended pinyin vowels (ā ē ě ī ǐ ō ǒ ū ǔ ǖ–ǜ), but Noto Sans Thai draws those marks too high/detached from the base letter — pinyin read as "วรรณยุกต์เยื้อง" (e.g. `chē`, `jǐ`, `nǚ`) — so Latin must resolve in Noto Sans first; Thai/Chinese chars are absent from Noto Sans and fall through to Noto Sans Thai / Noto Sans SC as before. `.match-card { font: inherit }` made the matching cards the visible case: the pinyin answer card now pins the stack itself via `.match-text[lang="zh-Latn"] { font-family: var(--font-pinyin) }` (the Thai answer card keeps `lang="th"`), and `.bomb-option` — which hard-coded `"Noto Sans Thai"` for pinyin options too — now uses `var(--font-ui)`. Loaded via the Google Fonts link in `index.html` (`Noto+Sans:wght@400;600;700`). `#menu`/`#setup` get a pure-CSS ambient backdrop (`::before` aurora drift + `::after` star layer, both `z-index: 0` + `pointer-events: none`, with `#menu > *, #setup > *` lifted to `z-index: 1` so they never cover buttons), the hero title splits the emoji from `.title-text` so the gradient `background-clip: text` doesn't erase the 🚀, and `.cards .card` gets a stagger entrance driven purely by `:nth-child` delays (no JS). Cards deliberately avoid `backdrop-filter` (11 blurred cards over an animated backdrop janks mid-range Android); only the single `.setup` panel uses it. A trailing `@media (prefers-reduced-motion: reduce)` block disables just these decorative animations — no game logic listens to `animationend`/`transitionend`, so this is safe. **Matching board polish** (เกมแฟลชการ์ดจับคู่): `#matchBoard` has a `::before` backdrop (radial spotlight + faint checkerboard, `z-index: -1`, `mask-image` falloff) and a 12px gap; every card gets a gloss strip (`.match-card::after`), a mouse-only lift on hover, a press-down transform, and a two-tone scheme where the Chinese card is warm/cream and the answer card (`.answer`, pinyin or Thai) is cool blue. Match states animate: `.selected` pulses, `.mismatch` shakes, and `.matched` **vanishes** — `matchVanish` runs with `forwards` so the card animates up then fades to `opacity: 0` and stays invisible *while still occupying its grid slot*, which is what keeps every other card from moving (a reduced-motion user gets an instant `opacity: 0; visibility: hidden` instead). Matched cards also get `pointer-events: none` + `aria-hidden="true"`. **the `.matched`/`.mismatch` rules must stay *after* `.selected` in style.css**, otherwise a card that is still selected (the mismatch pair stays selected until `waitUntil`) keeps the pulse instead of the shake. `matchFx()` (game.js) appends a transient `.match-ring` + `.match-float` (`+10` / `+15 … คอมโบ x2`) — now to **`#matchBoard`, positioned from the card's `offsetLeft/offsetTop`** (the older in-card version died together with the fading card); because the board can therefore contain non-card children, `renderMatchingCards()` and `flipMatchingCard()` must look cards up with `board.querySelectorAll(".match-card")`, never `board.children[i]`. The same trap also means `#matchFeedback` must keep a **constant height**: it is `nowrap` with `min-height: calc(clamp(28px,7vw,44px) * 1.6 + 28px)`, its spans scale by `--fb-scale` which `fitMatchFeedback()` shrinks until the line fits, and the "ครบชุดแล้ว" message lives in the absolutely-positioned `.match-round-done` overlay on the board instead of inside the box — without this the box grew 69→98px on a match and shrank the whole board (~9% smaller cards) on every single match. `.match-text` uses `font-weight: 600` (Noto Sans Thai's semibold is actually loaded) and `700` for Chinese, because Noto Sans SC is fetched as `400;700;900` only — the previous `800` snapped up to 900 and read as too heavy; the pinyin/Thai spans in `#matchFeedback` are `400`. Matching scores on a combo (10 → 15 → 20 → 25 → 30, reset on a mismatch, `s.combo`) and nudges the music intensity; `#matchProgTrack` (in index.html, driven by `updateMatchingHUD`) shows pairs-cleared-this-round progress and turns red with the timer's `.urgent`. `fitMatchCardText` searches up to 72px / 48px (Chinese / other) and re-fits after `document.fonts.ready`, because `.match-text` wraps (`overflow-wrap: anywhere`) instead of `white-space: nowrap`.

- Speaking practice mode (`speak`, เกมฝึกพูด): shows a SENTENCES entry (HSK 1–5), auto-plays its zh audio, then grades the user's speech. ASR reuses the dict-mode pipeline (Web Speech `zh-CN` + `loadDictWhisper`/`dictResample16k` Whisper fallback on `network` error or >7s stall). Grading is `spkAlign` — a Levenshtein alignment over Chinese chars only (`normZh` strips punctuation); homophones count as correct (same tone-stripped pinyin via the sentence's own pinyin or `dictPinyinIndex`), traditional chars are mapped through `TRAD2SIMP` for Whisper output. Green/red per-char verdict in `#spkCard`, "คุณพูดว่า" transcript in `#spkHeard`; wrong answers replay the correct audio and retry the same sentence. No background music (it would bleed into the mic); best score key `cr_best_hsk<level>_speak`.
- Sentence copying mode (`copy`, เกมเขียนเป็นประโยค): shows a random SENTENCES entry (HSK 1–5) for the user to copy into a notebook — shuffled deck with no repeats until exhausted (`cpAdvance`), auto-plays zh audio via `speakSentence`, no score/lives, plays the `sentence` music theme. Tapping a token chip (`cpOpenStrokes`) opens an inline HanziWriter `loopCharacterAnimation` stroke-order viewer reusing `loadBombLibrary()` + the shared `bombCharData` cache (one persistent `cpWriter` instance, `updateDimensions` on reopen/resize via `cpStrokeFit`, per-char chips via `cpStrokePlay`). "ข้าม" and "ประโยคถัดไป" both call `cpAdvance`. The sentence is spoken once at the start via `speakSentence`, and in `cpWriteMode === "on"` each character is read aloud as soon as it is written — `cpWriteCompleteChar` calls `speakChar(cp.writeChars[cp.writeIndex])` (pre-generated clip, **not** `speak()`; see the note under Pre-generated speech about WebView having no `speechSynthesis`); no character is exempt here, so the last character also reads just itself (unlike the bomb game, which reads the full word on its last character). In `cpWriteMode === "on"` (เขียนในเกม) the advance button lives inside `#cpWrite` as `#cpWriteNextBtn` (`.cpw-next`, directly under the character chips) and stays `disabled`/grey until `cp.writeIndex` reaches `cp.writeChars.length` — `cpWriteNextEnabled()` is driven from `renderCpWriteChips()`; the duplicate `#cpNextBtn` in the bottom bar is hidden so the gating can't be bypassed (use "ข้าม" to skip, e.g. when stroke data fails to load). The writing box is deliberately **small** — `CP_WRITE_MAX = 130` px (≈ half the original 260; CSS `#cpWriteWriter { width: min(130px, 34vw) }`), `cpWriteFit()` clamps to ≥ 90 px and `cpWritePad(size)` keeps HanziWriter's inner padding at ~6 % of the box — because a full-size box felt too big to write in with a real pen (a stylus writes fine, the box just doesn't need to be that big); `cpWriteFit()` re-runs on `resize` and the configured width/height must equal the rendered SVG size, otherwise HanziWriter's stroke coordinates drift. Tapping a word in the sentence (`cpRender` builds `#cpZh` via `cpRenderSentence` — one `.cp-zh-tok` button per `s[4]` token) opens the floating `#cpWordPopup` with pinyin + Thai meaning (+ POS from VOCAB_EXTRA, `cpWordPos`) anchored above the tapped word — no extra panel, works in both write modes. Lookup is `cpLookupWord` over a `cpWordIndex()` map built from VOCAB HSK 1–9 (handles `爸爸｜爸` variant pairs and TRAD2SIMP for traditional input); a whole-word miss falls back to greedy `cpSegment` so 航空公司 shows 航空 + 公司. Close button, outside `pointerdown`, Escape, scroll, or a new sentence call `cpHideWordPopup`; `resize` re-anchors it while the tapped word still exists.
- Sentence copying, free-writing option (`cpWriteMode === "free"`, 🖊️ เขียนแบบอิสระ — third value of the `cr_copy_write_mode` setting, next to off/on): one continuous long strip (`#cpFree` = canvas over `#cpFreeGrid`) that wraps the sentence's Chinese chars into a `repeat(cols, cell)` grid — `cols = min(n, floor(width / CP_FREE_MIN_CELL))`, `cell = min(104, floor(width / cols))`, and `CP_FREE_GAP = 0` so the cells touch and read as **one continuous row divided by faint dashed frames** (notebook look, `--cpfree-ink` = `rgba(160,186,232,.38)`; `.cpfree-cell` has `border-left-style: none` for the joined edge, and `cpFreeLayout()` tags each row's first/last cell with `.rowstart`/`.rowend` so the left frame line and the outer corner radii come back at every line break — `CP_FREE_GAP` must stay in sync with `.cpfree-grid` in style.css) — you write the whole sentence in one go and get graded **once** on a single 🔍 ตรวจ; ≥ `CP_FREE_MIN` (70%) unlocks ✅ ประโยคถัดไป inside the panel (the bottom-bar `#cpNextBtn` is hidden, "ข้าม" still skips). Ink capture reuses the dict-pad pattern (DPR-aware canvas, `touch-action: none`, `setPointerCapture`, `pencilSound` gated by `pencilAllowed()`) and stores points in **cell units** (`px / cpFreeCell`, 1 = one cell side) so a resize/DPI change can't distort stroke shapes; the pen is deliberately thin (`CP_FREE_PEN_W()` = `clamp(cell × 0.045, 2.2, 4.2)` px, ~4px on a 104px cell) so the ghost character stays readable while copying, the in-progress stroke is drawn in opaque `CP_FREE_INK` (per-segment strokes would double-darken at the joints with alpha) while every committed stroke is repainted in the translucent `CP_FREE_INK_SOFT` (`rgba(143,216,255,.66)`) so the guide shows through the ink you already wrote, and the guide text itself uses its own brighter token `--cpfree-guide` (`.5`) vs `--cpfree-ink` (`.38`) for the dashed frames; `#cpFreeCanvas` is `position:absolute; inset:0` in `.cpfree-stage`, which **must keep `width: 100%`** — the panel reuses `.dict-strokes` (a *centering* flex column), so without an explicit width the stage sizes itself from its own grid and collapses the whole strip into a permanent 2-column layout (measured 160px). Guides are plain text inside the cells (coloured by `--cpfree-guide`; `.cpfree-grid.no-guide` makes them transparent), so the existing "เส้นนำการเขียน" toggle (`cpOutline`, row now shown for any `cpWriteMode !== "off"`) drives this mode too. Scoring is fully offline off the shared `bombCharData` cache: `cpFreeGroups()` first **normalises the ink of each row onto the grid** (`clampK` keeps the affine factor inside [0.75, 1.35]: a global vertical pass maps the ink to the row count so strokes can be bucketed into rows, then a per-row horizontal pass maps that row's ink span onto its cells) and only then assigns each stroke to the nearest cell centre (`cpFreeCellCenter`, computed from the index — no DOM measuring). Do **not** go back to bucketing raw stroke centroids against the cell centres: that breaks as soon as the handwriting drifts, is spaced tighter/looser than the boxes or is written continuously like a notebook (the strokes that cross a box edge land in the neighbour, mixing two characters into one cell and dropping a correct attempt to ~30-40 % — verified: +0.12 cell/char drift scored 83 %, +0.2 59 %, shifted 0.35 cell 58 %, bunched spacing 66 % before, and 95-98 % after the normalisation); a monotone gap-splitting DP was tried too and rejected (it cannot recover characters whose strokes interleave in x, and it can merge several characters into one cell). **The `medians` in hanzi-writer-data are y-UP** — that is why HanziWriter renders every character with `scale(…, -…)` (`translate(0, 175.78) scale(0.195, -0.195)`) — while the user's ink is in screen coordinates (y down), so the target **must** be passed through `cpFreeFlipY()` before it is normalised/scored; without that flip the scorer compares the handwriting against a vertically mirrored character, i.e. the user has to write every character **upside down** to reach 100% (measured on the same ink: normal writing 41 % / upside-down 95 % before the flip, 95 % / 41 % after). Then strokes are matched **stroke-by-stroke in order** (proportional index mapping) against the character's `medians` after both sides are resampled to `CP_FREE_CFG.rc` points and normalised to a unit box (uniform scale + centred); each pair is scored on Chamfer shape distance + start/end point distance + length ratio + direction (weights/tolerances in `CP_FREE_CFG`, calibrated with synthetic ink: sloppy-but-correct handwriting ≈ 85–91%, scribbles / wrong character / whole-char-in-one-stroke ≤ 45%), the mean is then multiplied by a stroke-count penalty (`countFloor`) — and a 1-stroke rendering of a multi-stroke character is capped at `singleScore` (0.5) so it can never reach the pass mark. The result renders per-cell `%` badges (`.cpfree-pct` + `.ok`/`.bad`) that **stay visible at all times** — they are pinned to each cell's top-right corner with a solid background and the font size set from `cpFreeCell` in `cpFreeApplyBadges()`, and `.cpfree-grid` carries `position: relative; z-index: 1; pointer-events: none` so the badges paint **above** the ink canvas while a finger/mouse still draws on the canvas underneath (never make the grid capture pointer events, or writing dies) — plus a big total; `cpFreeApplyBadges()` re-applies them after a reflow. Writing or undoing a stroke calls `cpFreeClearResult()` (badges + total + the advance button reset) because the previous score no longer applies. `cpFreeReflow()` re-lays out on resize and only drops the ink when the column count changes; `cpFreeSetup()` schedules one `requestAnimationFrame` reflow because the first measurement can land before the screen has a size. Writing boxes never shrink below `CP_FREE_MIN_CELL` (84px) — `cpFreeColsFor` divides the panel width by that, so a long sentence wraps onto more rows instead of squeezing the cells (a 15-char sentence ends up 3 rows of 92px, a 48-char one 7 rows instead of the old 10 columns of 64px; the strip is the last thing on a `overflow-y: auto` screen, and the canvases's `touch-action: none` means panning has to start outside it). Eraser: `#cpFreeEraseBtn` (🩹, in `.cpfree-actions`) toggles `cpFree.eraser` through `cpFreeSetEraser()`, which also adds `.on` to the button / `.erasing` to `#cpFree` (yellow button + `cursor: cell` + an inset ring on the strip) and resets the in-flight stroke; in that mode `cpFreeDown`/`cpFreeMove` call `cpFreeEraseAt()` instead of drawing — it removes the **single nearest** stroke whose point-to-segment distance (`cpFreeStrokeDist`) is inside `cpFreeEraseRadius()` (~10–13px, `max(10, cell × 0.13)`), so tapping and dragging both erase, taps outside every stroke do nothing, and the pencil sound is skipped (`pencilSound` gated on `!cpFree.eraser`); erasing calls `cpFreeClearResult()` (the old score no longer applies) and the mode is turned off again on every new sentence (`cpFreeSetup`) and in `cpFreeHide()`.

Writing is **sequential**: only one slot is active at a time (others `.locked`), the slot's characters run one after another via `HanziWriter.quiz()` (same options as `cpWriteChar`: `leniency 1.4`, `markStrokeCorrectAfterMisses 4`, outline on/off from `tcOutline`) — `tcQuizChar` sets `showHintAfterMisses: 1` so the red hint (the stroke you should have drawn, `highlightColor #e5484d`) shows from the **first** wrong attempt; that number must stay below `markStrokeCorrectAfterMisses` (4), because on the attempt that auto-accepts a stroke HanziWriter takes the success branch and skips the hint render entirely — the old `tcOutline ? 4 : 1` meant the red hint could never appear while the guide was on (the default), so mistakes had no on-screen feedback until ✅ ตรวจ (`cpWriteChar` uses the same `showHintAfterMisses: 1` for the same reason — its hint line is green, `highlightColor #26a477`), and when a slot finishes `tcCompleteSlot` activates the next not-done slot. The score is **deferred**: per-stroke mistakes are accumulated in `slot.chars[k].wrongStrokes`/`attempts` but nothing is shown until all N slots are done and the user presses `#tcCheckBtn` (`tcCheck`), which scores `(strokes − wrongStrokes)/strokes` per char, averages the slots → %, saves `cr_best_hsk<level>_trace`, marks each slot ⭐ (perfect) or `✗ n`, and reveals the correct character (`showOutline`) plus a **persistent red overlay** of the wrong strokes (`tcMarkWrong` draws polylines from `bombCharData.medians` mapped with `getScreenCTM()` into an absolutely-positioned `.tc-wrong-overlay` SVG — the transient `highlightStroke` fades, so we draw our own). `#tcRetryBtn` ("ลองใหม่ช่องที่ผิด") resets only the wrong slots and re-activates them; `#tcNextBtn`/`#tcSkipBtn` draw the next non-repeating word. Async chains are invalidated by a **globally unique** `tcSeqCounter` (never resets per word — a per-word counter let stale chains from a previous word/session collide and crash on `slot.cells[k]`); writers also expose `_tcResolve` so `stopTrace`/`nextTraceWord` can unblock a pending `tcQuizChar`.
