- Background music: per-mode synth-orchestra playlists in `MUSIC_THEMES` (game.js) — each mode key (meteor/vocab/sentence/fillblank/zombie/matching/bomb/trace) holds an array of 5 unique song objects; `music.start("<mode>")` shuffles them and loops forever (each song = 32-step melody repeated `SONG_LOOPS` times, then `advanceSong` moves on; reshuffle avoids repeating the last song). Per-song fields: bpm, waveform, 32-step melody (null = rest), 8-step bass roots, drum flags, mul — shared per-mode defaults live in `_MET`/`_VOC`/`_SEN`/`_FIL`/`_ZOM`/`_MAT`/`_BOM`/`_TRA` spread into each song, plus the newer swing/pad/arp/detune/base (see below). `dict` and `speak` modes play no music. **Signal graph** (`music.buildGraph()`): per-layer gains (`drums/bass/pad/arp/lead/perc`, send amounts in `LAYER_FX`) → dry + reverb/delay sends → `master` (mute + `duckMusic`) → **two cascaded highpass biquads (`MUSIC_HP = 78` Hz, 24 dB/oct)** → `trim` (`MUSIC_TRIM = 0.85`) → `DynamicsCompressor` limiter → destination. The highpass is not cosmetic: the bass voice carries a `sub: 0.45` sub-oscillator an octave below (≈55 Hz) held through almost the whole bar and every `kick()` sweeps 155 → 44 Hz, so *before* the filter 15–27 % of the song's energy sat below 70 Hz (45–65 Hz was literally the loudest band in several songs). A phone speaker cannot move that far, so it bottomed out and buzzed — heard as constant "noise" under every song in every mode in the APK, while the same graph is clean on PC speakers/headphones (podcast/listen MP3s are speech-only, which is why they never showed it). The filter drops 45–65 Hz by ~7 dB and 35–50 Hz by ~8–9 dB, leaves the 110 Hz bass fundamental intact, and the `trim` puts the level back where it was (removing the rumble let ~1.2 dB more through the limiter). Do not "restore the bass" by removing it without testing on a real phone speaker. Reverb is a `ConvolverNode` with an **impulse response generated in JS** (`makeIR`, noise × power decay, no asset) and is skipped when `navigator.hardwareConcurrency <= 4`; the delay is a tempo-synced ping-pong (dotted-8th, synced in `syncDelay()` — which must be called again *after* `getAC()` builds the graph, since `loadSong()` runs before it). **Voices** (`music.tone`): 1 + 2 detuned oscillators (level divided by √n so loudness matches the old single-osc voice) + optional sub-oscillator for bass + per-voice lowpass with envelope + full ADSR + `StereoPanner` (`pan`); percussion lives in `kick/snare/hat/shaker/tom/bell/crash` plus a shared 1-second noise buffer (`nz`), with humanized timing (`human()`). **Song structure** is derived, not authored: `chordAt(s)` guesses each half-bar chord from `roots[0]`/`roots[4]` + the melody's third (3 semitones = minor, 4 = major), `pad()` holds that chord in 3 voices spread across the stereo field, `arp()` cycles its chord tones as 8th notes, drum fills (`tom`) land on the last 2 steps of every other loop and a `crash` opens the loop after. **Adaptive music**: `music.setIntensity(0..1)` (also `nudge()`) opens layers progressively in `applyIntensity()` (perc from .45, arp from .3, pad/lead/drums get slightly louder); intensity decays toward the mode's `base` at 0.7%/step, is reset to `base` on `music.start()`, and is driven by the game at: bomb mode (`renderBombTimer` → `1 - frac` remaining), meteor (`hitGround` → `1 - lives/3`), and every correct/wrong answer (`sfx.correct`/`sfx.wrong` → `nudge(+.05/-.12)`).

Scoring is fully offline off the shared `bombCharData` cache: `cpFreeGroups()` first **normalises the ink of each row onto the grid** (`clampK` keeps the affine factor inside [0.75, 1.35]: a global vertical pass maps the ink to the row count so strokes can be bucketed into rows, then a per-row horizontal pass maps that row's ink span onto its cells) and only then assigns each stroke to the nearest cell centre (`cpFreeCellCenter`, computed from the index — no DOM measuring). Do **not** go back to bucketing raw stroke centroids against the cell centres: that breaks as soon as the handwriting drifts, is spaced tighter/looser than the boxes or is written continuously like a notebook (the strokes that cross a box edge land in the neighbour, mixing two characters into one cell and dropping a correct attempt to ~30-40 % — verified: +0.12 cell/char drift scored 83 %, +0.2 59 %, shifted 0.35 cell 58 %, bunched spacing 66 % before, and 95-98 % after the normalisation); a monotone gap-splitting DP was tried too and rejected (it cannot recover characters whose strokes interleave in x, and it can merge several characters into one cell). **The `medians` in hanzi-writer-data are y-UP** — that is why HanziWriter renders every character with `scale(…, -…)` (`translate(0, 175.78) scale(0.195, -0.195)`) — while the user's ink is in screen coordinates (y down), so the target **must** be passed through `cpFreeFlipY()` before it is normalised/scored; without that flip the scorer compares the handwriting against a vertically mirrored character, i.e. the user has to write every character **upside down** to reach 100% (measured on the same ink: normal writing 41 % / upside-down 95 % before the flip, 95 % / 41 % after). Then strokes are matched **stroke-by-stroke in order** (proportional index mapping) against the character's `medians` after both sides are resampled to `CP_FREE_CFG.rc` points and normalised to a unit box (uniform scale + centred); each pair is scored on Chamfer shape distance + start/end point distance + length ratio + direction (weights/tolerances in `CP_FREE_CFG`, calibrated with synthetic ink: sloppy-but-correct handwriting ≈ 85–91%, scribbles / wrong character / whole-char-in-one-stroke ≤ 45%), the mean is then multiplied by a stroke-count penalty (`countFloor`) — and a 1-stroke rendering of a multi-stroke character is capped at `singleScore` (0.5) so it can never reach the pass mark. The result renders per-cell `%` badges (`.cpfree-pct` + `.ok`/`.bad`) that **stay visible at all times** — they are pinned to each cell's top-right corner with a solid background and the font size set from `cpFreeCell` in `cpFreeApplyBadges()`, and `.cpfree-grid` carries `position: relative; z-index: 1; pointer-events: none` so the badges paint **above** the ink canvas while a finger/mouse still draws on the canvas underneath (never make the grid capture pointer events, or writing dies) — plus a big total; `cpFreeApplyBadges()` re-applies them after a reflow. Writing or undoing a stroke calls `cpFreeClearResult()` (badges + total + the advance button reset) because the previous score no longer applies. `cpFreeReflow()` re-lays out on resize and only drops the ink when the column count changes; `cpFreeSetup()` schedules one `requestAnimationFrame` reflow because the first measurement can land before the screen has a size. Writing boxes never shrink below `CP_FREE_MIN_CELL` (84px) — `cpFreeColsFor` divides the panel width by that, so a long sentence wraps onto more rows instead of squeezing the cells (a 15-char sentence ends up 3 rows of 92px, a 48-char one 7 rows instead of the old 10 columns of 64px; the strip is the last thing on a `overflow-y: auto` screen, and the canvases's `touch-action: none` means panning has to start outside it).
